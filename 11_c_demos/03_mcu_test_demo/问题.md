我一般来说先让他看，看完描述执行流程。然后问这个led_port_init在做啥，这个write_pin的类型是什么，描述一下。再问这个led_bind_port在做啥，这个g_led_port->write_pin的这个write_pin实际调用的是哪个函数。这个gpio是什么类型，为什么选void*。为什么led_开头的函数第一个参数要选择led_t*。一轮问一下，基本上差不多看得懂水平了。不行就问led_state什么类型，led_t什么类型。

- **初级：** 问语法，问指针，看基础。
- **中级：** 问架构，问移植，看经验。
- **高级：** 问扩展性，问并发，问设计模式，看天花板。

| 代码                                      | 涉及的知识点                                                 |
| :---------------------------------------- | :----------------------------------------------------------- |
| `typedef struct ... led_t`                | 结构体对齐、C++兼容性、内存布局、标签命名规范                |
| `void (*write_pin)(void* gpio, u8 state)` | **函数指针**（C语言核心难点）、回调机制、函数指针数组        |
| `void* gpio`                              | **通用指针**、类型安全、显式强转、内存模型                   |
| `led_bind_port(..., void* gpio)`          | **依赖注入**（设计模式）、运行时绑定、解耦思想               |
| `u32`, `u8`                               | 数据类型标准、跨平台移植性、stdint.h 规范                    |
| `static` 关键字                           | 作用域限制、封装性、防止符号冲突                             |
| 整体架构                                  | **分层设计**、HAL（硬件抽象层）思想、OOP（面向对象思想）、RTOS预备 |
